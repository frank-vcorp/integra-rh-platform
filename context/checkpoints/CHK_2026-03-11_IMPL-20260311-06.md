## Cambios Detallados

### Tarea 1 — Layout & Cards (UI base)
- **Reemplazado** el Accordion de "Mis Candidatos" por una **Tabla/Grid ejecutiva** con columnas:

- **Semáforo visual** implementado con `SemaforoBadge` (círculo de color ●):
  - 🟢 Verde = Módulo completado
  - 🟡 Amarillo = En progreso
  - 🔴 Rojo = Requiere atención
  - ⚪ Gris = Pendiente / No aplica
- Cada módulo muestra **tooltip** explicativo (sin revelar datos internos del analista)
- Leyenda visual en el encabezado de la card
- Diseño responsive con `overflow-x-auto`

- Esto incluye el campo calculado `investigacionProgreso` (% de avance de historial laboral) en la respuesta del portal
- El cálculo es in-memory basado en el estatus de cada WorkHistory item

## Lógica del Semáforo

```typescript
// Laboral: basado en investigacionLaboral del proceso
getSemaforoLaboral(inv) → 
  - verde   si inv.completado === true
  - amarillo si inv.resultado || inv.detalles (datos parciales)
  - gris    si sin datos

// Visita: basado en visitStatus del proceso
getSemaforoVisita(vs) →
  - verde   si vs.status === "realizada"
  - amarillo si vs.status === "programada" | "asignada"
  - gris    si sin status o "no_asignada"

// Documental (Legal): basado en investigacionLegal del proceso
getSemaforoDocumental(leg) →
  - verde   si leg.antecedentes (verificado)
  - rojo    si leg.flagRiesgo === true
  - gris    si sin datos
```

- `servicios` (qué módulos aplican al proceso) se determina con `getServiciosIncluidos` existente
- La tabla es "1 fila = 1 candidato con su proceso más reciente"
