## Resumen ejecutivo

Se implementó la estrategia HTML-first para la generación del PDF de Armados. El `editorialSnapshot` ahora recorre un único camino editorial:

```
snapshot → renderArmadoHtml() → HTML autocontenido → Playwright → PDF
                                                          ↓ (si falla)
                                               generarArmadoClientePDF() [fallback]
```

El PDF final deriva del mismo HTML que se usa para el preview interno. No hay segunda narrativa separada.

## Comportamiento implementado

### Camino principal (HTML-first)
1. `createLegacyReportDraft` llama a `renderArmadoHtml(snapshot, sections)` → HTML editorial autocontenido
2. Ese HTML se pasa a `renderHtmlToPdf(html)` en `armadoPdfFromHtml.ts`
3. Playwright lanza Chromium headless, `page.setContent()` + `page.pdf({ format: "A4", printBackground: true })`
4. El buffer resultante se sube a Firebase Storage como el PDF final del armado
5. El campo `rendererUsed: "html_headless"` queda en el audit log y en la respuesta del mutation

### Fallback (pdf-lib legado)
Se activa automáticamente cuando:
- `@playwright/test` no puede importarse (producción sin devDeps)
- El binario de Chromium no existe en disco
- Playwright lanza un error (sandbox, OOM, timeout)

En fallback: `rendererUsed: "pdf_lib_legacy"` — trazabilidad registrada en audit log.

### Trazabilidad completa
```typescript
// En el audit log de cada versión generada:

  ...
  rendererUsed: "html_headless" | "pdf_lib_legacy",
}

// En la respuesta del mutation createLegacyReportDraft:
{ id, versionNumber, storagePath, rendererUsed }
```

## Limitaciones conocidas

| Limitación | Impacto |
|------------|---------|
| `@playwright/test` es devDependency — en Docker de producción sin devDeps, siempre cae a fallback | Bajo si el Dockerfile instala el binario por separado (ver nota abajo) |
| El HTML editorial no incluye imágenes externas (fotos del domicilio) por diseño de seguridad del renderer | Aceptable — las evidencias visuales están en Storage, no en el entregable cliente |
| `page.pdf()` de Playwright genera una numeración de páginas distinta al fallback pdf-lib | Cosmético — el número de páginas correcto se calcula al renderizar |

**Nota sobre producción:** Para activar el camino HTML-first en Docker, agregar en el Dockerfile:
```dockerfile
RUN npx playwright install chromium --with-deps
```
o incluir el paquete `playwright` en `dependencies` (no en devDependencies).
