## Resumen de Hallazgos

### Error Reportado
- **Síntoma Principal:** HTTP 500 cuando usuario accede a `ProcesoDetalle`
- **Queries Fallando Simultáneamente:**
  1. `surveyors.listActive`
  2. `clients.list`
  3. `candidates.list`
  4. `posts.list`
  5. `processes.list`

### Análisis Técnico Ejecutado

#### 1. Mapeo del Origen
✅ **Ubicación Confirmada:** `/integra-rh-manus/client/src/pages/ProcesoDetalle.tsx` línea 52-199
- 5 hooks `useQuery()` se lanzan en batch sin parámetros
- input: `null`, meta.values: `["undefined"]`
- Se disparan al componente renderizarse

#### 2. Estructura de Código Revisada
✅ **Routers:** Todos 5 están correctamente implementados en `/integra-rh-manus/server/routers/`
- `surveyorsRouter.listActive` → `adminProcedure`
- `clientsRouter.list` → `protectedProcedure` + `requirePermission("clientes", "view")`
- `candidatesRouter.list` → `publicProcedure` con lógica fallback
- `postsRouter.list` → `protectedProcedure` con validación por rol
- `processesRouter.list` → Protegido, habilitado condicionalmente

✅ **Base de Datos:** Funciones en `/db.ts` son correctas
- `getAllClients()`, `getAllPosts()`, `getCandidatesWithInvestigationProgress()`, `getAllSurveyors()`
- Todas retornan `[]` si `getDb()` === null, esto es **CRÍTICO**
- `getDb()` puede retornar `null` si `DATABASE_URL` no está set o conexión falla

#### 3. Root Cause PROBABLE (No Confirmado - Requiere DEBY)
**Sospecha Primaria:** `DATABASE_URL` missing o conexión MySQL fallida en Railway
- Si `getDb()` retorna `null`, las 5 funciones retornan arrays vacíos
- Pero middleware tRPC podría estar interpretando esto como error serialización
- Generaría HTTP 500 en batch request

**Sospecha Secundaria:** Middleware `requirePermission` en `clients.list` + `posts.list`
- Si `ctx.user` está corrompido o `ctx.permissions` vacío, throws 403
- Pero error se propaga como HTTP 500 en batch
